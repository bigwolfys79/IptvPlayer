# Принцип работы IptvPlayer

Техническое описание того, как приложение устроено изнутри: откуда берутся данные, как парсятся и сопоставляются плейлисты и EPG, как всё отрисовывается, и как работают логотипы и архив передач. Имена классов/методов — реальные, из кода.

## Общая схема

```
M3U-плейлист (провайдер)          XMLTV-источники EPG (epg.one и др.)
        │                                    │
        ▼                                    ▼
M3UParserService ──► PlaylistCache   XmlTvService ──► EpgCacheStore (MemoryPack+Brotli)
        │            (playlist_cache.json)         │
        ▼                                            ▼
ChannelRepository ──────────────►  EPGService (слияние источников + индексы)
        │                                    │
        ▼                                    ▼
MainPage / ViewModels ◄──────── сопоставление канал↔EPG (4 пути)
        │
        ▼
StreamService ──► FFmpegInteropX/FFmpeg ──► MediaPlayerElement (видео)
```

Ключевые классы:
- `Services/M3UParserService` — парсинг M3U/M3U8 в `ChannelViewModel`.
- `Services/PlaylistCacheService` + `Models/PlaylistCache` — кэш плейлиста на диске.
- `Services/XmlTvService` — скачивание и парсинг XMLTV, кэш через `Services/EpgCacheStore`.
- `Services/EPGService` — слияние источников, индексы сопоставления, логотипы.
- `Assets/epg-name-map.json` — таблица «имя → tvg-id» сервиса epg.one/setup-playlist.
- `MainPage` (+ `ViewModels/MainPageViewModel`, `EpgViewModel`, `ChannelViewModel`) — весь UI и оверлеи.
- `Services/StreamService` — создание плеера (FFmpegInteropX).

---

## 1. Запуск приложения

`MainWindow` → `MainPage` → `InitializeAsync()` (страница показывается сразу, ничего не блокирует):

1. Загружаются настройки (`SettingsService`, `%LocalAppData%\IptvPlayer\settings.json`); из них восстанавливается громкость.
2. **Плейлист**: берётся из кэша, если он не просрочен (`PlaylistRefreshDays`, 0 = никогда) и его `FormatVersion` актуален. Иначе — скачивается и парсится заново. Если скачивание упало, а кэш (пусть просроченный) есть — показываются каналы из кэша.
3. Каналы кладутся в `ChannelRepository` (именно из него EPGService берёт список), получают `Id`, заполняют `ViewModel.Channels`.
4. `SelectedChannel` назначается сразу, `Task.Yield()` даёт UI отрисовать список каналов — **до** загрузки EPG.
5. Фоном запускается `EpgViewModel.LoadEPGAsync()` → `EPGService.EnsureEpgLoadedAsync()`: программы и логотипы догружаются и появляются по мере готовности.

Каждый шаг тяжёлой работы (десериализация кэша, парсинг XML, слияние источников) выполняется через `Task.Run` в пуле потоков — UI-поток занят только быстрыми операциями.

## 2. Плейлист: парсинг и кэш

**Формат.** Строки `#EXTINF:<duration> атрибуты,Название` + URL потока. Парсер (`M3UParserService.ParseExtinf`):
- название — всё после **последней** запятой (устойчиво к запятым внутри атрибутов);
- атрибуты: `tvg-id`, `tvg-logo`, `group-title` (или fallback-группа) и признаки архива: `tvg-rec`, `catchup-days`, `catchup` (у этого провайдера — `tvg-rec="7"`; нечисловое значение типа `default` трактуется как 1 день).

**Кэш** (`PlaylistCache` в `playlist_cache.json`): минимальный набор полей на канал (`Name`, `StreamUrl`, `LogoUrl`, `Group`, `TvgId`, `CatchupDays`) + `SavedAtUtc` + `FormatVersion`. Версия формата введена специально: при добавлении новых полей старый кэш считается устаревшим и плейлист один раз перекачивается при первом запуске обновлённого приложения. Кэш хранится **отдельно** от EPG-кэша и не стирается кнопкой «Обновить EPG».

## 3. EPG: скачивание, парсинг, кэш

**Источники** — список URL XMLTV в настройках (основной: полный фид `epg.one/epg.xml.gz`, 45 МБ gzip / 420 МБ XML / ~420 тыс. передач). `XmlTvService.LoadAsync`:

1. **Чтение кэша** (`EpgCacheStore`): файл `%LocalAppData%\IptvPlayer\cache\<sha256(url)>.mpck.br` — бинарная сериализация MemoryPack + сжатие Brotli. Чтение 420 тыс. передач занимает < 1 с (JSON занимал ~5–8 с при 280 МБ). Свежесть кэша определяется по `SavedAtUtc`/`maxAge` из настроек (`EpgRefreshDays`). При первом запуске новой версии выполняется **миграрация**: старый JSON-кэш читается один раз и пересохраняется в новый формат — без перекачки по сети.
2. **Скачивание** (HttpClient, таймаут 3 мин) → определение gzip по содержимому (не по расширению) → распаковка → `ParseXmlTv` в `Task.Run`. Парсится только **окно дат** ±3 дня (`DaysBack/DaysAhead`, назад — от начала суток): всё вне окна отбрасывается. Для каждого канала собираются передачи (`EPGEntry`) и `<icon src>` (словарь логотипов по tvg-id).
3. **Запись кэша** — тоже в фоне, атомарно (через `.tmp` + переименование).

**Слияние источников** (`EPGService.MergeSources`, пул потоков): источники обрабатываются в порядке списка настроек; программы группируются по `ChannelId`; передача из менее приоритетного источника отбрасывается, если пересекается по времени с уже принятой; иконки берутся от первого источника, где нашлись. Затем каждая группа сортируется по `StartTime`.

## 4. Сопоставление каналов с EPG

Плейлист этого провайдера **вообще не содержит tvg-id**, поэтому работают четыре пути — от надёжного к приблизительному (`EPGService.MatchChannel`):

1. **tvg-id плейлиста** — точное совпадение с `ChannelId` в XMLTV (для будущих плейлистов).
2. **Таблица epg.one** (`Assets/epg-name-map.json`, генерируется из m3u8 сервиса epg.one/setup-playlist, 3218 записей): **строгий ключ** — нормализованное имя с сохранённым таймшифтом («Первый канал +2» имеет собственный tvg-id → корректное расписание со сдвигом);
3. **Мягкий ключ** той же таблицы — нормализованное базовое имя (при конфликте вариантов побеждает самое короткое имя = базовый канал);
4. **Индекс нормализованных имён XMLTV** (`BuildNameIndex`) — резерв для имён, которых нет в таблице.

**Нормализация** (`NormalizeChannelNameCore`): нижний регистр, ё→е, срез суффикса `.ru/.ua`, содержимого скобок (регионы), маркеров качества (HD/FHD/UHD/SD/4K/HEVC), таймшифта `+N`, хвостовых кодов стран (UK/FR/DE… + international/международный) и маркеров потока (orig, 50/60 fps, hdr, 1080p…); алиасы вида «кинозал→кино». Голый `+` превращается в слово `plus` (чтобы «BCU Kids+» не схлопывался с «BCU Kids»).

**Конфликты имён в XMLTV**: если несколько id нормализуются в одно имя —
- различие только в качестве (HD/SD/4K) → выбирается один id (максимум передач, затем максимальное качество);
- настоящее неоднозначность (разные регионы) → детерминированно выбирается лучший кандидат, имя попадает в агрегированную строку лога (чтобы видеть, где расписание эвристическое);
- для брендовых префиксов («Tviksel Кино 2 HD» → ключ «кино 2») добавляются дополнительные ключи, только если не заняты прямыми именами.

Итог по текущему плейлисту: ~2043 из 2065 каналов с EPG (98%); остальные (Триколор-«Кинозалы», сезонные) расписаний не имеют ни в одном источнике.

## 5. Отрисовка

Слои правой области задаются `Canvas.ZIndex`: видео (1) → EPG-оверлей (2) → панель управления видео (3) → индикатор загрузки EPG (4).

**Список каналов** (`ChannelItemTemplate`): логотип (28×28) → точка-индикатор архива (зелёная/серая, `BoolToLiveColorConverter` по `HasArchive`) → название + текущая передача (`CurrentProgramTitle`, `Mode=OneWay`). Текущая передача пересчитывается таймером раз в минуту (`RefreshCurrentProgramsLightAsync` — обновляются только заголовки, без пересборки коллекций).

**EPG-панель** (`EpgPanelBorder`) — перекрывающий оверлей, по умолчанию скрыт; кнопка EPG в панели управления открывает/закрывает; при открытии список прокручивается к текущей передаче. Каждая карточка передачи показывает время, длительность, название, описание и значок архива (`CanPlayArchive` — передача уже началась). Текущая передача подсвечена зелёной рамкой (`IsCurrent`).

**Панель управления видео** (`WindowedVideoOverlay`): пауза архива, «В эфир», громкость, EPG, настройки, полноэкранный режим. Появляется по движению мыши (`RightPanelGrid` → `VideoArea_PointerMoved`), скрывается сама через 3 с (общий `_overlayHideTimer`); fade-анимация защищена флагом «fade-in уже идёт» — иначе оверлей успевал появиться только после остановки мыши. В полноэкранном режиме те же функции у полноэкранного оверлея (список каналов + управление).

**Громкость**: слайдер (оба оверлея синхронны), колесо мыши над видео (шаг 5%), сохранение в настройки с дебаунсом 700 мс.

**Клавиатура** (`OnPagePreviewKeyDown`, MainPage): обработчик повешен на **корневой элемент XamlRoot** (подписка после Loaded) — туннелирующее событие идёт от корня к сфокусированному элементу, а окно хостит страницу внутри Grid+Frame, поэтому подписка на самой странице пропускала клавиши, пока фокуса внутри страницы нет (Ctrl+J «не работал»). Корень ловит всё; открытые ContentDialog отсекаются проверкой фокуса (`IsFocusedWithin(ContentDialog)`). Пробел — пауза архива; ↑/↓ и PgUp/PgDn — соседний канал по кругу в пределах `DisplayedChannels` (в fullscreen показывается оверлей — имя канала в его шапке); M — беззвучный режим (`PlayerViewModel.ToggleMute`: громкость в 0 без затирания `LastUserVolume`, восстановление при снятии; кнопки M в обеих панелях, слайдеры программно в ноль); F/F11 и двойной клик по `VideoAreaBorder` — полный экран (двойной клик по «пустым» местам видимого полноэкранного оверлея — фон/шапка — тоже, `FullScreenOverlay_DoubleTapped`: прозрачный фон оверлея перехватывает клики над видео; клики по кнопкам/слайдерам/списку игнорируются); Esc — выход; V — режим отображения видео (`CycleVideoStretch`: Uniform→Fill→UniformToFill, `MediaPlayerElement.Stretch`, сохраняется в `AppSettings.VideoStretch`); Ctrl+J — оверлей статистики (в fullscreen — под шапкой, Margin правее/ниже списка каналов); Ctrl+F — фокус в поиск с выделением текста; цифры — ввод номера канала с оверлеем `ChannelNumberOverlay` (ZIndex 5, не ловит мышь): Enter/таймаут 3 с — коммит, Backspace — стереть, Esc — отмена. Ограничения перехвата: в полях ввода работают только Ctrl+F; стрелки/PgUp/PgDn не перехватываются при фокусе на списке/слайдере перемотки/комбобоксе (`IsNavigationControlFocused` — обход предков через `VisualTreeHelper`). Буквенные клавиши приходят VK-кодами латиницы независимо от раскладки.

## 6. Логотипы каналов

Три источника, по приоритету (`EPGService.ApplyMissingLogosAsync`, вызывается после загрузки EPG):
1. `tvg-logo` из плейлиста (этот провайдер не отдаёт — всегда пусто);
2. `<icon src>` из XMLTV (по tvg-id);
3. `tvg-logo` из таблицы epg.one (`_logoByTvgId` — тот же файл, из которого берутся tvg-id; 3218 логотипов на epg.one/img/…).

Кандидаты tvg-id для поиска: собственный `TvgId` канала → строгий ключ → мягкий ключ (те же пути, что и сопоставление). Найденный URL пишется в `ChannelViewModel.LogoUrl` (INotifyPropertyChanged), картинка рисуется через `StringToImageSourceConverter` (BitmapImage с системным кэшем — повторные скроллы не перекачивают). Заполнение — только для каналов с пустым `LogoUrl`, логика в логе: «Подставлено логотипов…».

## 7. Архив передач (timeshift)

**Признак.** Глубина архива берётся из `tvg-rec`/`catchup-days` плейлиста (906 из 2065 каналов: 3 или 7 дней) и хранится в `ChannelViewModel.CatchupDays`. От него зависит зелёная точка в списке каналов и подсказка с глубиной архива.

**Запуск.** Клик по уже начавшейся передаче в EPG (`EPGProgramsListView_ItemClick`): `ArchiveUrlBuilder.BuildUrl` добавляет к live-URL два параметра — `utc` (epoch-секунды начала передачи; времена EPG локальные, `DateTimeOffset` корректно переводит их в epoch) и `lutc` (текущий момент). Провайдер сам отдаёт сдвинутый плейлист с валидными подписями сегментов. Запущенная передача: EPG-оверлей автоматически скрывается, в панели управления появляются кнопки «В эфир» (возврат к прямой трансляции, `PlayLiveAsync`) и пауза (только для архива), в полноэкранном оверлее — индикатор архива.

**Перемотка.** HLS-timeshift не ищется на лету, поэтому полоса перемотки в панелях управления работает перезапуском: позиция считается в `PlayerViewModel` по стенным часам от старта показа (минус суммарное время пауз — паузы учитываются при возобновлении), слайдер с подписями `мм:сс / ч:мм:сс` обновляется секундным таймером MainPage, отпускание ползунка (`PointerReleased`/`PointerCaptureLost`, а если события не дошли — дебаунс `ValueChanged`) перезапускает поток через тот же `ArchiveUrlBuilder` с новой точкой старта (не дальше 5 с от живого эфира). Модель полосы: ноль — начало передачи, максимум — её конец (вся передача целиком, масштаб не меняется); точка старта показа входит в позицию слагаемым, поэтому после перемотки индикатор остаётся на перемотанной минуте, а не падает в ноль; позиция не заходит дальше живого эфира.

Ограничение: передача должна была начаться (и лежать в окне ±3 дня парсинга EPG) и в пределах глубины архива провайдера — иначе `MediaFailed` с записью в лог.

## 8. Воспроизведение

`StreamService.CreatePlayerAsync` — единая точка создания плеера (на каждый канал новый `MediaPlayer`):

1. **FFmpegInteropX + FFmpeg** — демуксинг и декодирование (системный HLS-стек Windows не декодирует HEVC в MPEG-TS, а AC-3 с 24H2 удалён из системы — FFmpeg закрывает всё). Конфигурация:
   - режим декодера из настроек: «аппаратный» = `VideoDecoderMode.Automatic` (GPU с откатом на CPU), «программный» = `ForceFFmpegSoftwareDecoder` (по умолчанию);
   - `DownmixAudioStreamsToStereo = false` — многоканальный звук сводит аудиодвижок Windows (downmix FFmpeg звучит тише);
   - упреждающая буферизация 15 с / 32 МБ — сглаживает стыки 10-секундных HLS-сегментов (платой является задержка от эфира ~10–15 с).
2. **Время жизни источника**: `FFmpegMediaSource` привязан к плееру через `ConditionalWeakTable` — без этого GC собирал источник посреди воспроизведения (рывки → пропажа звука → крах 0xC00D36B6).
3. **Откат**: если FFmpeg не смог открыть URL — системный `MediaSource.CreateFromUri` (для H.264-каналов работает и без FFmpeg).
4. **Диагностика**: при успешном открытии StreamService снимок параметров потока (кодеки, разрешение, битрейты, выбранный `DecoderEngine` и `HardwareDecoderStatus`, буфер) кладётся в `CurrentDiagnostics` — оверлей статистики (Ctrl+J, `StatsOverlay` в MainPage) читает снимок, а живые метрики добавляет сам (простои — счётчик `BufferingStarted` за текущий канал, время сессии); обновление — секундным тиком. Заполнение буфера не показывается: `PlaybackSession.BufferingProgress` у живых MediaStreamSource-потоков всегда 0, а реальный read-ahead буфер живёт внутри FFmpegInteropX и наружу не отдаётся.
5. Ошибки плеера логируются с кодами (`CurrentPlayer_MediaFailed` → `MediaPlayer.MediaFailed` в лог Serilog, см. §10).

**Закрытие приложения**: подписка на `MainWindow.Closed` останавливает/освобождает плеер и вызывает `Environment.Exit(0)` — иначе медиа-конвейер держал процесс живым несколько секунд после закрытия окна.

## 9. Данные на диске

| Что | Где |
|---|---|
| Настройки (источники, периодичности, громкость, режим декодера) | `%LocalAppData%\IptvPlayer\settings.json` |
| Кэш плейлиста | `%LocalAppData%\IptvPlayer\playlist_cache.json` |
| Кэш EPG (MemoryPack+Brotli, ~9,5 МБ на источник) | `%LocalAppData%\IptvPlayer\cache\*.mpck.br` |
| Таблица «имя → tvg-id» + логотипы | `Assets\epg-name-map.json` (в составе приложения) |
| Лог (Serilog, ежедневный роллинг + 14 дней хранения) | `%LocalAppData%\IptvPlayer\logs\iptvplayer-*.log` |

В MSIX-режиме (Debug) пути `%LocalAppData%` виртуализуются в пакет; в unpackaged-режиме (Release/Inno) используются напрямую — код одинаково работает в обоих.

## 10. Логирование и DI

**Serilog.** Статический логгер настраивается первым делом в конструкторе `App` (до `InitializeComponent` — глобальные обработчики исключений уже должны писать в лог): два sink'а — Debug (окно Output под отладчиком, всегда) и файловый (`%LocalAppData%\IptvPlayer\logs`, ежедневный роллинг, лимит 10 МБ/файл, 14 последних файлов). Формат строки сохранён от самописного предшественника: `время [уровень] [источник] сообщение`. Классы получают `ILogger<T>` (Microsoft.Extensions.Logging поверх Serilog через `Serilog.Extensions.Logging`) конструктором — источник в логе = имя класса; статический контекст (App, EpgCacheStore) пишет в `Serilog.Log` напрямую. Файловый лог выключается тумблером в настройках на лету: `LoggingLevelSwitch` файлового sink'а поднимается выше Fatal (`App.SetFileLoggingEnabled`), состояние — `AppSettings.FileLoggingEnabled`, применяется на старте (до создания логгера, чтобы файл вообще не создавался) и сразу при переключении.

**DI.** `App` — composition root: `ServiceCollection` собирается в конструкторе, провайдер доступен как `App.Services`. Все сервисы и ViewModel'ы — singletons (одна сессия, одно окно); конкретные типы (`ChannelRepository`, `EPGService`) регистрируются отдельно от интерфейсов. Страницы резолвят зависимости через `App.Services.GetRequiredService` в конструкторе — WinUI не даёт внедрять их в конструкторы XAML-элементов. Все прежние `?? new SomeService()`-фолбэки и разрозненные `new SettingsService()` убраны: теперь ровно один экземпляр на сервис.
